# EXTERNAL_APP_INTEGRATION

## 1. ドキュメントの目的

本ドキュメントは、個トレアプリが連携する外部システムとの役割、
連携内容および担当範囲を定義する。

本ドキュメントでは以下を明確に区別して管理する。

- 業務仕様
- コードから確認できた事実
- 未確認事項

## 3. スキマ君

### 3.1 システム概要（業務仕様）

スキマ君は、個トレアプリとは別プロジェクトの学習アプリである。

主に以下の学習を行う。

- 英単語
- 古文単語
- 化学式
- その他の暗記教材

また、小テスト機能を持つ。

### 3.2 個トレアプリとの関係（業務仕様）

個トレアプリは、スキマ君の学習機能を持たない。

個トレアプリでは以下を行う。

- スキマ君の起動
- 利用ログ管理
- 小テスト結果確認

### 3.3 個トレアプリからの起動（業務仕様）

生徒は個トレアプリへログインした状態からスキマ君を起動する。

Google Apps Scriptを利用し、
個トレアプリ側のユーザー情報を利用して
スキマ君側で必要な認証処理を行う。

生徒がスキマ君側で再度ログイン情報を入力しなくても
利用開始できることを業務仕様とする。

### 3.4 コードから確認できた事実

現在のフロントコードでは、Google Apps Scriptの`issueToken`を呼び出し、
返却されたトークンとユーザーIDを利用して
スキマ君を開く処理が確認されている。

### 3.5 未確認事項

以下は現時点では確認できていない。

- GAS内部での認証処理
- ユーザーID照合方法
- パスワード利用有無
- トークン生成方法
- トークン有効期限
- トークン失効処理
- スキマ君側認証処理
- GASとスキマ君間のデータ受け渡し

これらはGASおよびスキマ君側コード調査後に確定する。

### 3.6 利用コンテンツ権限連携

- GASの`validateToken`は個トレアプリ経由のトークン認証成功時に、`login`はスキマ君での通常ログイン成功時に、生徒の`allowedContentIds`と`permissionsInitialized`を返す。
- 起動方法にかかわらず同じコンテンツマスターと生徒別権限を使用し、同じ利用制御を適用する。
- `allowedContentIds`は、実行時に「スキマ君コンテンツ」マスターと生徒別権限から生成する。初期登録用の21件を実行時の正本にはしない。
- 表示名と固定内部識別子を分離し、スキマ君側との権限連携には`contentId`を使用する。
- 利用権限値を起動URLへ直接含めない。
- スキマ君側は`allowedContentIds`を利用し、未許可コンテンツのメニュー表示、直接URLアクセス、教材取得、小テスト開始および結果保存を拒否する責任を持つ。
- 権限情報はGASの管理データを正とし、クライアントから送信された権限値だけを信用しない。
